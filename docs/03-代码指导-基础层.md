**三个必须注意的点**：

1. **`pgvector/pgvector:pg16` 镜像**。用官方 `postgres:16` 的话，扩展装不上（要么编译，要么手动装包），第一天就卡住。
2. **Langfuse 用自己的数据库**。它跑 `prisma migrate`，会往库里建一堆表。和业务表同库会污染 `\dt` 输出，也让"我能不能直接连业务库"变得危险。第一个 compose 起来后手动建库：
   ```bash
   docker compose exec postgres psql -U oncall -c "CREATE DATABASE langfuse;"
   ```
3. **不要一上来就 `docker compose up -d`**。下面是分层启动，见下一节。

### 分层启动（profile 的用法）

上面给 `mcp-*` / `api` / `worker` / `alertgen` / `ui` / `langfuse` 都加了 `profiles`，**只有 `postgres` 和 `redis` 不带 profile**。这带来一个很舒服的性质：**`docker compose up -d` 默认只起基础设施那两个**，其他的必须显式 `--profile` 才起。

| 阶段 | 命令 | 实际起了几个 | 大概吃多少内存 |
|---|---|---|---|
| **W1** 地基 | `docker compose up -d` | 2（postgres, redis） | ~400 MB |
| **W2** MCP 层 | `docker compose --profile mcp up -d` | 6 | ~1 GB |
| **W3-W7** 打链路 / 图 / HITL | `docker compose --profile mcp --profile app up -d` | 10 | ~2 GB |
| **W10** 上可观测 | `docker compose --profile mcp --profile app --profile obs up -d` | 11 | ~3~4 GB |

**为什么必须这么做**：11 个容器一起跑要 3~4 GB 内存。一台 16GB 的笔记本同时开着 IDE、浏览器、Docker Desktop（WSL2 虚拟机本身就要 1GB 起），可用内存往往只剩几百 MB —— 全开会直接把机器拖死，或者容器被 OOM 杀掉，然后你以为是代码写错了。

> 💡 **忘了带 `--profile` 是最常见的坑**：明明写了 `mcp-logs` 服务，`docker compose ps` 里却看不见它。**不是写错了，是没启用 profile。**
>
> 排查命令（**注意第一个命令的坑**）：
> ```bash
> # ❌ 只列出"不带 profile"的服务，你会以为其他服务不存在
> docker compose config --services              # → 只有 postgres, redis
>
> # ✅ 要显式带上 profile 才能看到全部
> docker compose --profile mcp --profile app --profile obs config --services   # → 11 个
>
> # 当前实际起着的
> docker compose ps
> ```

**W1 阶段就记住一句话**：`docker compose up -d` = 只起 postgres + redis。

## 4. Redis：去重与锁

```python
# app/services/dedup.py
import hashlib
import json

import redis.asyncio as aioredis

from app.config import settings

_pool: aioredis.Redis | None = None


def get_redis() -> aioredis.Redis:
    global _pool
    if _pool is None:
        _pool = aioredis.from_url(str(settings.redis_dsn), decode_responses=True)
    return _pool


def alert_fingerprint(payload: dict) -> str:
    """告警指纹：同一组 label 视为同一告警。

    用 Alertmanager 自带的 fingerprint 更好；这里做兜底，
    因为手工灌的测试告警没有这个字段。
    """
    labels = payload.get("labels", {})
    key = "|".join(
        f"{k}={labels.get(k, '')}"
        for k in ("alertname", "service", "instance", "severity")
    )
    return hashlib.sha1(key.encode()).hexdigest()[:16]


async def try_claim_alert(fingerprint: str, ttl: int | None = None) -> bool:
    """尝试认领一条告警。

    SET key val NX EX ttl 是原子操作：
      - NX  = 键不存在才设置（防重复）
      - EX  = 过期时间（防内存泄漏）
    返回 True 表示是我第一次处理，False 表示重复告警，应该丢弃。
    """
    ttl = ttl or settings.alert_dedup_ttl_s
    ok = await get_redis().set(f"alert:fp:{fingerprint}", "1", nx=True, ex=ttl)
    return bool(ok)


def build_idempotency_key(plan_id: int, action: str, target: str, params: dict) -> str:
    """幂等键 = 方案 + 动作 + 目标 + 参数的稳定哈希。

    用 sort_keys 保证同一个 dict 不同插入顺序得到同一个哈希。
    """
    body = json.dumps(
        {"plan": plan_id, "action": action, "target": target, "params": params},
        sort_keys=True, ensure_ascii=False, separators=(",", ":"),
    )
    return hashlib.sha256(body.encode()).hexdigest()


class action_lock:
    """执行期的分布式锁：防止同一个动作被两个 worker 同时执行。

    用 async with 语法糖，确保异常路径也会释放锁。
    """

    def __init__(self, key: str, ttl: int | None = None):
        self.key = f"lock:action:{key}"
        self.ttl = ttl or settings.action_lock_ttl_s
        self.token: str | None = None

    async def __aenter__(self) -> bool:
        import uuid
        self.token = uuid.uuid4().hex
        ok = await get_redis().set(self.key, self.token, nx=True, ex=self.ttl)
        return bool(ok)

    async def __aexit__(self, *exc) -> None:
        # 只释放自己持有的锁 —— 用 Lua 保证"检查 token + 删除"是原子的，
        # 否则可能删掉别人超时后重新获取的锁
        lua = (
            "if redis.call('get', KEYS[1]) == ARGV[1] "
            "then return redis.call('del', KEYS[1]) else return 0 end"
        )
        try:
            await get_redis().eval(lua, 1, self.key, self.token)
        except Exception:
            pass
```

**面试必问**：「你的锁为什么用 Lua 脚本释放？」
答：如果先 `GET` 判断是不是自己的 token、再 `DEL`，这两步之间锁可能刚好过期、被别的进程拿走，于是你删掉了别人的锁。Lua 脚本在 Redis 里单线程原子执行，把"检查+删除"合成一步。**这是分布式锁的经典陷阱，能主动讲出来就是加分。**

## 5. MCP Server 实现

### 5.1 共用的 mock 数据层

4 个 server 都从同一个"假生产环境"读数据。数据放在 Postgres 里（不是内存），这样重启不丢、多进程共享。

```python
# mcp_servers/store.py
"""mock 生产环境数据访问层。

四个 MCP server 共用。真实世界里这里会换成：
  logs     → Loki / ES 的 HTTP API
  metrics  → Prometheus 的 /api/v1/query_range
  cmdb     → 内部 CMDB API
  executor → K8s API / 发布平台 API
换的时候只改这个文件，agent 侧一行不动。
"""
from datetime import datetime, timedelta, timezone

from sqlalchemy import text

from app.db.base import SessionLocal


async def fetch_logs(
    service: str, pattern: str | None, minutes: int, limit: int, level: str | None
) -> list[dict]:
    since = datetime.now(timezone.utc) - timedelta(minutes=minutes)
    sql = text("""
        SELECT ts, level, service, message, trace_id
        FROM mock_logs
        WHERE service = :service
          AND ts >= :since
          AND (:level IS NULL OR level = :level)
          AND (:pattern IS NULL OR message ILIKE :pattern)
        ORDER BY ts DESC
        LIMIT :limit
    """)
    async with SessionLocal() as s:
        rows = await s.execute(sql, {
            "service": service, "since": since,
            "level": level, "pattern": f"%{pattern}%" if pattern else None,
            "limit": limit,
        })
        return [dict(r._mapping) for r in rows]


async def aggregate_log_stats(service: str, minutes: int) -> dict:
    since = datetime.now(timezone.utc) - timedelta(minutes=minutes)
    sql = text("""
        SELECT level, count(*) AS cnt
        FROM mock_logs
        WHERE service = :service AND ts >= :since
        GROUP BY level
    """)
    async with SessionLocal() as s:
        rows = (await s.execute(sql, {"service": service, "since": since})).all()

    by_level = {r.level: r.cnt for r in rows}
    total = sum(by_level.values())
    errors = by_level.get("ERROR", 0) + by_level.get("FATAL", 0)
    return {
        "service": service,
        "window_minutes": minutes,
        "total": total,
        "errors": errors,
        "error_rate": round(errors / total, 4) if total else 0.0,
        "by_level": by_level,
    }


async def fetch_metric_points(service: str, metric: str, minutes: int, step: int) -> list[dict]:
    since = datetime.now(timezone.utc) - timedelta(minutes=minutes)
    sql = text("""
        SELECT ts, value FROM mock_metrics
        WHERE service = :service AND metric = :metric AND ts >= :since
        ORDER BY ts
    """)
    async with SessionLocal() as s:
        rows = await s.execute(sql, {"service": service, "metric": metric, "since": since})
        return [{"ts": r.ts.isoformat(), "value": float(r.value)} for r in rows]


async def fetch_recent_changes(service: str, hours: int) -> list[dict]:
    since = datetime.now(timezone.utc) - timedelta(hours=hours)
    sql = text("""
        SELECT id, kind, operator, at, detail, "commit"
        FROM mock_changes
        WHERE service = :service AND at >= :since
        ORDER BY at DESC
    """)
    async with SessionLocal() as s:
        rows = await s.execute(sql, {"service": service, "since": since})
        return [
            {**dict(r._mapping), "at": r.at.isoformat(), "commit": r.commit}
            for r in rows
        ]
```

> 这三张 `mock_*` 表也走 Alembic 迁移管理（放在第二个迁移文件里），别用 `create_all`。

### 5.2 日志 MCP Server

```python
# mcp_servers/logs_server.py
"""日志检索 MCP Server。

启动：python -m mcp_servers.logs_server
协议：streamable-http，路径 /mcp
"""
import logging
from collections import Counter
from datetime import datetime, timezone

from fastmcp import FastMCP

from app.config import settings
from mcp_servers import store

logging.basicConfig(level=settings.log_level)
log = logging.getLogger("mcp.logs")

mcp = FastMCP(
    name="logs",
    instructions=(
        "提供生产环境日志检索能力。查询时优先用聚合类工具"
        "（error_rate / top_error_patterns）定位方向，再用 search_logs 看细节，"
        "避免一次拉取大量原始日志。"
    ),
)


@mcp.tool
async def error_rate(service: str, minutes: int = 30) -> dict:
    """查询某服务最近 N 分钟的日志总量、错误数和错误率。

    Args:
        service: 服务名，例如 api-gateway
        minutes: 回溯窗口（分钟），默认 30
    """
    return await store.aggregate_log_stats(service, minutes)


@mcp.tool
async def search_logs(
    service: str,
    pattern: str | None = None,
    minutes: int = 30,
    level: str | None = None,
    limit: int = 50,
) -> dict:
    """按关键字或级别检索原始日志。

    Args:
        service: 服务名
        pattern: 关键字（大小写不敏感的模糊匹配），如 "timeout"
        minutes: 回溯窗口（分钟）
        level: 日志级别过滤，ERROR / WARN / INFO / FATAL
        limit: 最多返回条数，上限 200
    """
    limit = min(limit, 200)
    rows = await store.fetch_logs(service, pattern, minutes, limit, level)
    # 只把 message 截断到 500 字符：防止一条超长堆栈把上下文吃光
    for r in rows:
        r["message"] = (r["message"] or "")[:500]
        r["ts"] = r["ts"].isoformat() if isinstance(r["ts"], datetime) else r["ts"]
    return {
        "service": service,
        "pattern": pattern,
        "window_minutes": minutes,
        "count": len(rows),
        "truncated": len(rows) >= limit,
        "lines": rows,
    }


@mcp.tool
async def top_error_patterns(service: str, minutes: int = 30, top: int = 5) -> dict:
    """把错误日志按模板粗聚类，返回最高频的几种错误模式。

    这是定位根因最高效的工具：先看"哪种错误最多"，
    而不是逐条读日志。

    Args:
        service: 服务名
        minutes: 回溯窗口（分钟）
        top: 返回前 N 种模式
    """
    rows = await store.fetch_logs(service, None, minutes, 2000, "ERROR")
    # 粗聚类：把数字、UUID、IP、十六进制串替换成占位符，
    # 这样 "timeout after 3s to 10.1.2.3" 和 "timeout after 7s to 10.9.9.9"
    # 会归到同一个模板
    import re

    def templatize(msg: str) -> str:
        msg = re.sub(r"\b[0-9a-f]{8}-[0-9a-f-]{27,}\b", "<UUID>", msg, flags=re.I)
        msg = re.sub(r"\b\d+\.\d+\.\d+\.\d+\b", "<IP>", msg)
        msg = re.sub(r"\b0x[0-9a-f]+\b", "<HEX>", msg, flags=re.I)
        msg = re.sub(r"\b\d+\b", "<N>", msg)
        return msg[:200]

    counter: Counter[str] = Counter()
    sample: dict[str, str] = {}
    for r in rows:
        tpl = templatize(r["message"] or "")
        counter[tpl] += 1
        sample.setdefault(tpl, r["message"])

    return {
        "service": service,
        "window_minutes": minutes,
        "scanned": len(rows),
        "patterns": [
            {"pattern": p, "count": c, "sample": sample[p]}
            for p, c in counter.most_common(top)
        ],
    }


@mcp.tool
async def get_trace(trace_id: str) -> dict:
    """按 trace_id 取出一次完整请求链路的日志，用于跨服务追踪。

    Args:
        trace_id: 链路 ID
    """
    from sqlalchemy import text
    from app.db.base import SessionLocal

    async with SessionLocal() as s:
        rows = await s.execute(
            text("SELECT ts, level, service, message FROM mock_logs "
                 "WHERE trace_id = :tid ORDER BY ts"),
            {"tid": trace_id},
        )
        lines = [
            {"ts": r.ts.isoformat(), "level": r.level, "service": r.service,
             "message": (r.message or "")[:500]}
            for r in rows
        ]
    return {"trace_id": trace_id, "count": len(lines), "lines": lines}


if __name__ == "__main__":
    log.info("starting logs MCP server on :8001")
    mcp.run(transport="streamable-http", host="0.0.0.0", port=8001)
```

**三个设计要点，面试要讲**：

1. **`error_rate` / `top_error_patterns` 这类聚合工具比 `search_logs` 更重要。** 让 LLM 读 2000 行原始日志既贵又容易跑偏。正确做法是**把聚合逻辑放在工具侧**（代码确定性强、可测试），只把结论喂给模型。这就是"工具要有洞察，不要当管道"。
2. **docstring 就是工具的 prompt。** FastMCP 会把函数签名和 docstring 转成 JSON Schema 给模型。所以 docstring 要写清"什么时候用"，不只是"是什么"。
3. **截断是必须的。** `message[:500]`、`limit<=200`、模板化聚类 —— 三道闸门防上下文爆炸。

```python
import logging
import statistics
from datetime import datetime, timezone

from fastmcp import FastMCP

from app.config import settings
from mcp_servers import store

logging.basicConfig(level=settings.log_level)
mcp = FastMCP(

    instructions="提供时序指标查询与异常检测。先用 detect_anomaly 找异常指标，再用 query_range 看曲线细节。",
)

# 允许查询的指标白名单 —— 防止 LLM 编造指标名
ALLOWED_METRICS = {
    "cpu_usage", "memory_usage", "request_rate", "error_rate",
    "p99_latency_ms", "p50_latency_ms", "connections", "qps",
    "db_pool_used", "db_pool_size", "cache_hit_rate", "gc_pause_ms",
    "restart_count", "disk_io_wait",
}


@mcp.tool
async def list_metrics(service: str) -> dict:
    """列出该服务可查询的指标名。不确定指标名时先调这个，不要猜。"""
    return {"service": service, "metrics": sorted(ALLOWED_METRICS)}


@mcp.tool
async def query_range(service: str, metric: str, minutes: int = 60, step: int = 60) -> dict:
    """查询指标在时间范围内的数据点。

    Args:
        service: 服务名
        metric: 指标名，必须来自 list_metrics
        minutes: 回溯窗口（分钟）
        step: 采样步长（秒）
    """
    if metric not in ALLOWED_METRICS:
        raise ValueError(f"unknown metric: {metric}. call list_metrics first.")

    points = await store.fetch_metric_points(service, metric, minutes, step)
    values = [p["value"] for p in points]
    return {
        "service": service, "metric": metric, "minutes": minutes,
        "count": len(points),
        "min": min(values) if values else None,
        "max": max(values) if values else None,
        "avg": round(statistics.fmean(values), 3) if values else None,
        # 点数多时抽样返回，避免上下文爆炸
        "points": points if len(points) <= 60 else points[:: max(len(points) // 60, 1)],
        "downsampled": len(points) > 60,
    }


@mcp.tool
async def detect_anomaly(service: str, metric: str, minutes: int = 60) -> dict:
    """检测指标是否异常，返回 z-score 和异常窗口。

    用最近 24 小时做基线，最近 N 分钟做对比窗口。
    |z| > 3 视为异常。

    Args:
        service: 服务名
        metric: 指标名
        minutes: 对比窗口（分钟）
    """
    if metric not in ALLOWED_METRICS:
        raise ValueError(f"unknown metric: {metric}")

    recent = await store.fetch_metric_points(service, metric, minutes, 60)
    baseline = await store.fetch_metric_points(service, metric, 24 * 60, 300)

    if not recent or len(baseline) < 5:
        return {"service": service, "metric": metric, "anomalous": False,
                "reason": "insufficient data"}

    rvals = [p["value"] for p in recent]
    bvals = [p["value"] for p in baseline]
    mean = statistics.fmean(bvals)
    stdev = statistics.pstdev(bvals) or 1e-9
    current = rvals[-1]

    return {
        "service": service, "metric": metric,
        "anomalous": abs((current - mean) / stdev) > 3,
        "z_score": round((current - mean) / stdev, 2),
        "current": round(current, 3),
        "baseline_mean": round(mean, 3),
        "baseline_stdev": round(stdev, 3),
        "peak": round(max(rvals), 3),
        "direction": "up" if current > mean else "down",
        "window_minutes": minutes,
    }


@mcp.tool
async def compare_to_baseline(service: str, metric: str, hours: int = 24) -> dict:
    """把当前值与历史基线对比，返回变化百分比。用于判断"是否真的变差了"。"""
    if metric not in ALLOWED_METRICS:
        raise ValueError(f"unknown metric: {metric}")

    recent = await store.fetch_metric_points(service, metric, 15, 60)
    hist = await store.fetch_metric_points(service, metric, hours * 60, 300)
    if not recent or not hist:
        return {"service": service, "metric": metric, "insufficient_data": True}

    cur = statistics.fmean([p["value"] for p in recent])
    base = statistics.fmean([p["value"] for p in hist]) or 1e-9
    return {
        "service": service, "metric": metric,
        "current": round(cur, 3), "baseline": round(base, 3),
        "delta_pct": round((cur - base) / base * 100, 2),
    }


if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="0.0.0.0", port=8002)
```

> **白名单的价值**：`ALLOWED_METRICS` 是**工具侧**的防护。LLM 编造指标名（`cpu_percent` vs `cpu_usage`）是常态，靠 prompt 提醒不可靠，靠代码抛错才可靠。**"约束写进代码，不写进 prompt"** 是贯穿整个项目的原则。

### 5.5 执行器 MCP Server（最关键的一个）

```python
# mcp_servers/executor_server.py
"""处置执行 MCP Server。端口 8004。

这是系统里唯一有"写权限"的组件，也是安全边界所在。
三条硬约束全部在这里实现，不依赖 prompt：
  1. 动作白名单
  2. 幂等键短路
  3. CRITICAL 动作必须有审批号
"""
import asyncio
import logging
from datetime import datetime, timezone

from fastmcp import FastMCP
from sqlalchemy import select

from app.db.base import SessionLocal
from app.db.models import Execution

mcp = FastMCP(
    name="executor",
    instructions=(
        "执行运维动作。所有动作都必须先 dry_run_action 预演。"
        "apply_action 会真正改变生产环境，只在获得人工审批后调用。"
    ),
)

# 动作白名单：不在表里的动作一律拒绝
ACTION_CATALOG: dict[str, dict] = {
    "restart_deployment": {
        "risk": "MEDIUM", "requires_approval": True,
        "description": "滚动重启服务的所有副本",
        "params_schema": {"service": "str", "grace_period": "int=30"},
    },
    "scale_deployment": {
        "risk": "MEDIUM", "requires_approval": True,
        "description": "调整服务副本数",
        "params_schema": {"service": "str", "replicas": "int"},
    },
    "rollback_deployment": {
        "risk": "HIGH", "requires_approval": True,
        "description": "回滚到上一个发布版本",
        "params_schema": {"service": "str", "to_revision": "str"},
    },
    "clear_cache": {
        "risk": "LOW", "requires_approval": False,
        "description": "清理缓存命名空间（低风险，可自动执行）",
        "params_schema": {"namespace": "str"},
    },
}

# 内存中的执行结果，仅供 mock 查询。真实实现里查执行平台的 API。
_FAKE_RESULTS: dict[str, dict] = {}


@mcp.tool
async def get_action_catalog() -> dict:
    """列出所有允许执行的动作及其风险等级。生成处置方案前必须先调这个。"""
    return {"actions": [{"action": k, **v} for k, v in ACTION_CATALOG.items()]}


@mcp.tool
async def dry_run_action(action: str, target: str, params: dict | None = None) -> dict:
    """预演一个动作，返回将要发生什么，但不产生任何实际影响。

    Args:
        action: 动作名，必须在 get_action_catalog 列出的清单里
        target: 目标服务名
        params: 动作参数
    """
    spec = ACTION_CATALOG.get(action)
    if not spec:
        raise ValueError(
            f"action '{action}' is not in the allow-list. "
            f"allowed: {sorted(ACTION_CATALOG)}"
        )
    return {
        "dry_run": True,
        "action": action,
        "target": target,
        "params": params or {},
        "risk": spec["risk"],
        "requires_approval": spec["requires_approval"],
        "effect": spec["description"],
        "warning": (
            f"This will affect {target} in production. "
            f"Risk level {spec['risk']}."
        ),
    }


@mcp.tool
async def apply_action(
    action: str,
    target: str,
    params: dict | None = None,
    idempotency_key: str | None = None,
    approval_id: int | None = None,
) -> dict:
    """真正执行运维动作。危险操作，只在审批通过后调用。

    Args:
        action: 动作名，必须在白名单内
        target: 目标服务名
        params: 动作参数
        idempotency_key: 幂等键，必填。同键重复调用不会重复执行
        approval_id: 审批记录 ID。CRITICAL/HIGH 风险动作必填
    """
    params = params or {}

    # ---- 约束 1：白名单 ----
    spec = ACTION_CATALOG.get(action)
    if not spec:
        raise ValueError(f"action '{action}' is not in the allow-list")
    if not idempotency_key:
        raise ValueError("idempotency_key is required")

    # ---- 约束 3：高危动作必须有审批号 ----
    if spec["risk"] in ("HIGH", "CRITICAL") and approval_id is None:
        raise ValueError(
            f"action '{action}' has risk {spec['risk']} and requires a valid approval_id"
        )

    # ---- 约束 2：幂等短路。先查库，已执行过就原样返回 ----
    async with SessionLocal() as s:
        existing = await s.scalar(
            select(Execution).where(Execution.idempotency_key == idempotency_key)
        )
        if existing is not None and existing.status == "succeeded":
            logging.getLogger("mcp.executor").info(
                "idempotent hit: key=%s reuse previous result", idempotency_key
            )
            return {
                "idempotent_replay": True,
                "action": action, "target": target,
                "status": existing.status,
                "result": existing.result,
                "executed_at": existing.finished_at.isoformat() if existing.finished_at else None,
            }

    # ---- 真的执行（mock：sleep 模拟耗时）----
    started = datetime.now(timezone.utc)
    await asyncio.sleep(1.5)
    result = {
        "action": action,
        "target": target,
        "params": params,
        "revision_before": "v42",
        "revision_after": "v42" if action != "rollback_deployment" else params.get("to_revision", "v41"),
        "affected_replicas": 6,
        "dry_run": False,
    }
    finished = datetime.now(timezone.utc)

    # 回写执行记录，让幂等短路在下次生效
    async with SessionLocal() as s:
        row = await s.scalar(
            select(Execution).where(Execution.idempotency_key == idempotency_key)
        )
        if row is not None:
            row.status = "succeeded"
            row.result = result
            row.finished_at = finished
            row.duration_ms = int((finished - started).total_seconds() * 1000)
            await s.commit()

    _FAKE_RESULTS[idempotency_key] = result
    return {
        "idempotent_replay": False,
        "status": "succeeded",
        "action": action, "target": target,
        "result": result,
        "duration_ms": int((finished - started).total_seconds() * 1000),
    }


@mcp.tool
async def get_action_status(idempotency_key: str) -> dict:
    """查询某个动作的执行状态。"""
    async with SessionLocal() as s:
        row = await s.scalar(
            select(Execution).where(Execution.idempotency_key == idempotency_key)
        )
    if row is None:
        return {"found": False, "idempotency_key": idempotency_key}
    return {
        "found": True, "idempotency_key": idempotency_key,
        "action": row.action, "target": row.target, "status": row.status,
        "result": row.result, "error": row.error,
        "duration_ms": row.duration_ms,
    }


@mcp.tool
async def rollback(idempotency_key: str) -> dict:
    """回滚之前执行过的一个动作。用于执行后验证失败的情况。"""
    status = await get_action_status(idempotency_key)
    if not status.get("found"):
        return {"ok": False, "reason": "execution not found"}
    await asyncio.sleep(1.0)
    return {
        "ok": True, "idempotency_key": idempotency_key,
        "message": f"rolled back {status['action']} on {status['target']}",
    }


if __name__ == "__main__":
    mcp.run(transport="streamable-http", host="0.0.0.0", port=8004)
```

**这个文件是面试的富矿，四个讲点**：

| 讲点 | 怎么说 |
|---|---|
| 权限边界 | "整个系统只有 executor 一个进程能写生产环境，诊断 Agent 拿到的三个工具全是只读的。这是进程级隔离，比函数里 if 判断可信。" |
| 约束在代码不在 prompt | "白名单校验写在 server 里，模型就算被注入了也绕不过去。" |
| 幂等 | "幂等键短路放在 server 侧而不是调用方 —— 因为调用方可能因为超时重试，重试时它自己也不知道上次成没成。" |
| 审批号强绑定 | "HIGH 风险动作要求 approval_id 非空，executor 不接受'我口头批准了'。审批记录在库里，可审计。" |

```python
async def seed_scenario(name: str, *, minutes: int = 60) -> dict:
    spec = SCENARIOS[name]
    service = spec["service"]
    now = datetime.now(timezone.utc)
    rng = random.Random(hash(name) & 0xFFFF)

    logs, metrics = [], []
    for i in range(minutes):
        ts = now - timedelta(minutes=minutes - i)
        # 故障在窗口的 60% 处开始 —— 保证"之前正常、之后异常"的形态
        broken = i > minutes * 0.6

        n_err = rng.randint(20, 60) if broken else rng.randint(0, 2)
        for _ in range(n_err):
            tpl = rng.choice(spec["log_templates"])
            logs.append({
                "ts": ts + timedelta(seconds=rng.randint(0, 59)),
                "level": "ERROR", "service": service,
                "message": tpl.replace("{n}", str(rng.randint(100, 9999))),
                "trace_id": f"tr-{rng.randint(10**11, 10**12 - 1):x}",
            })
        for _ in range(rng.randint(5, 15)):
            logs.append({
                "ts": ts + timedelta(seconds=rng.randint(0, 59)),
                "level": "INFO", "service": service,
                "message": f"handled request path=/api/{rng.choice(['order', 'user', 'cart'])} status=200",
                "trace_id": None,
            })

        for metric, (lo, hi) in spec["metrics"].items():
            ratio = (i / minutes) if broken else rng.uniform(0, 0.15)
            metrics.append({
                "ts": ts, "service": service, "metric": metric,
                "value": round(lo + (hi - lo) * ratio + rng.uniform(-lo * 0.05, lo * 0.05), 3),
            })

    change_at = now - timedelta(minutes=int(minutes * 0.55))
    changes = [{
        "service": service, "kind": spec["change"]["kind"],
        "operator": rng.choice(["alice", "bob", "carol"]),
        "at": change_at, "detail": spec["change"]["detail"],
        "commit": f"{rng.randint(0x1000000, 0xFFFFFFF):x}",
    }]

    async with SessionLocal() as s:
        await s.execute(text("DELETE FROM mock_logs WHERE service = :svc"), {"svc": service})
        await s.execute(text("DELETE FROM mock_metrics WHERE service = :svc"), {"svc": service})
        await s.execute(text("DELETE FROM mock_changes WHERE service = :svc"), {"svc": service})
        if logs:
            await s.execute(
                text("INSERT INTO mock_logs (ts, level, service, message, trace_id) "
                     "VALUES (:ts, :level, :service, :message, :trace_id)"),
                logs,
            )
        if metrics:
            await s.execute(
                text("INSERT INTO mock_metrics (ts, service, metric, value) "
                     "VALUES (:ts, :service, :metric, :value)"),
                metrics,
            )
        await s.execute(
            text('INSERT INTO mock_changes (service, kind, operator, at, detail, "commit") '
                 "VALUES (:service, :kind, :operator, :at, :detail, :commit)"),
            changes,
        )
        await s.commit()

    return {
        "scenario": name, "service": service,
        "logs": len(logs), "metrics": len(metrics),
        "root_cause_tags": spec["root_cause_tags"],
    }


async def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--scenario", choices=sorted(SCENARIOS))
    ap.add_argument("--all", action="store_true")
    ap.add_argument("--minutes", type=int, default=60)
    args = ap.parse_args()

    names = sorted(SCENARIOS) if args.all else [args.scenario]
    for n in names:
        print(await seed_scenario(n, minutes=args.minutes))


if __name__ == "__main__":
    asyncio.run(main())
```

**为什么造数据要造"故障形态"而不是随机数**：随机数生成的指标曲线没有"变更点"，Agent 的异常检测和变更关联就无从下手。**每个场景都必须有一个明确的因果链**（变更 → 指标劣化 → 错误日志），否则评估集没有标准答案。

```python
"""定时向自家 webhook 灌假告警，模拟真实告警流。

用法：python -m mockenv.alertgen --interval 120

import time

import httpx

API = "http://api:8000"


def build_alertmanager_payload(scenario: str) -> dict:
    """构造一个严格符合 Alertmanager webhook 格式的载荷。

    格式对齐真实 Alertmanager，后续换成真告警时不用改接收端。

    spec = SCENARIOS[scenario]
    service = spec["service"]
    names = {
        "memory_leak": ("HighMemoryUsage", "critical"),
        "bad_release": ("HighErrorRate", "critical"),
        "db_deadlock": ("DBPoolExhausted", "warning"),
        "cpu_saturation": ("HighCPUUsage", "warning"),
        "cache_miss_storm": ("LowCacheHitRate", "warning"),
    }
    alertname, severity = names[scenario]
    now = datetime.now(timezone.utc).isoformat()

    return {
        "version": "4",
        "groupKey": f'{{}}:{{alertname="{alertname}", service="{service}"}}',
        "status": "firing",
        "receiver": "oncall-copilot",
        "groupLabels": {"alertname": alertname, "service": service},
        "commonLabels": {"alertname": alertname, "service": service, "severity": severity},
        "commonAnnotations": {
            "summary": f"{service} {alertname}",
            "description": f"scenario={scenario}; see runbook",
        },
        "externalURL": "http://alertmanager:9093",
        "alerts": [{
            "status": "firing",
            "labels": {
                "alertname": alertname, "service": service, "severity": severity,
                "instance": f"{service}-{random.randint(0, 5)}",
                "scenario": scenario,        # 只有 mock 才有，评估集用它做 ground truth
            },
            "annotations": {"summary": f"{service} {alertname} firing"},
            "startsAt": now,
            "endsAt": "0001-01-01T00:00:00Z",
            "generatorURL": f"http://prometheus:9090/graph?g0.expr={alertname}",
            "fingerprint": f"fp-{scenario}",
        }],
    }


async def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--interval", type=int, default=120)
    ap.add_argument("--once", action="store_true")
    args = ap.parse_args()

    async with httpx.AsyncClient(timeout=30) as client:
        while True:
            scenario = random.choice(sorted(SCENARIOS))
            payload = build_alertmanager_payload(scenario)
            try:
                r = await client.post(f"{API}/webhook/alertmanager", json=payload)
                print(f"[{time.strftime('%H:%M:%S')}] {scenario} -> {r.status_code} {r.text[:120]}")
            except Exception as e:
                print(f"send failed: {e}")
            if args.once:
                return
            await asyncio.sleep(args.interval)


if __name__ == "__main__":
    asyncio.run(main())
```

## 7. MCP Client

```python
# app/agent/mcp_client.py
"""MCP 客户端：把 4 个 MCP server 的工具装进 LangChain Tool 列表。

启动时加载一次并缓存 —— 工具列表是静态的，不用每次调用都握手。
"""
import logging

from langchain_core.tools import BaseTool
from langchain_mcp_adapters.client import MultiServerMCPClient

from app.config import settings

log = logging.getLogger(__name__)

# 只读工具（诊断阶段可用）
READONLY_SERVERS = ("logs", "metrics", "cmdb")
# 写工具（只在 execute 节点显式使用）
WRITE_SERVERS = ("executor",)

_client: MultiServerMCPClient | None = None
_tools_by_server: dict[str, list[BaseTool]] = {}
_tools_by_name: dict[str, BaseTool] = {}


def _server_config() -> dict:
    """MCP server 连接配置。

    transport="streamable_http" 是 MCP 现行推荐的远程传输；
    stdio 适合本地子进程场景，本项目用 http 因为 server 是独立容器。
    """
    return {
        "logs":     {"url": settings.mcp_logs_url,     "transport": "streamable_http", "timeout": settings.mcp_timeout_s},
        "metrics":  {"url": settings.mcp_metrics_url,  "transport": "streamable_http", "timeout": settings.mcp_timeout_s},
        "cmdb":     {"url": settings.mcp_cmdb_url,     "transport": "streamable_http", "timeout": settings.mcp_timeout_s},
        "executor": {"url": settings.mcp_executor_url, "transport": "streamable_http", "timeout": 60.0},
    }


async def init_mcp_tools() -> dict[str, list[BaseTool]]:
    """在 FastAPI lifespan / worker 启动时调用一次。"""
    global _client, _tools_by_server, _tools_by_name
    _client = MultiServerMCPClient(_server_config())

    for server in READONLY_SERVERS + WRITE_SERVERS:
        try:
            tools = await _client.get_tools(server_name=server)
            _tools_by_server[server] = tools
            for t in tools:
                _tools_by_name[t.name] = t
            log.info("mcp server '%s' loaded %d tools: %s",
                     server, len(tools), [t.name for t in tools])
        except Exception as e:
            # 单个 server 挂掉不应让整个应用起不来 —— 降级运行，缺哪个工具就少哪路证据
            log.error("failed to load mcp server '%s': %s", server, e)
            _tools_by_server[server] = []

    return _tools_by_server


def get_tool(name: str) -> BaseTool:
    if name not in _tools_by_name:
        raise KeyError(f"tool '{name}' not loaded. available: {sorted(_tools_by_name)}")
    return _tools_by_name[name]


def readonly_tools() -> list[BaseTool]:
    """诊断阶段绑定给 LLM 的工具集 —— 不含 executor。"""
    out: list[BaseTool] = []
    for s in READONLY_SERVERS:
        out.extend(_tools_by_server.get(s, []))
    return out


def tools_for_kinds(kinds: list[str]) -> list[BaseTool]:
    """按证据类型取工具。

    kind → server 映射：
      logs → logs, metrics → metrics, changes/topology → cmdb
    """
    mapping = {
        "logs": ["logs"],
        "metrics": ["metrics"],
        "changes": ["cmdb"],
        "topology": ["cmdb"],
    }
    names: set[str] = set()
    for k in kinds:
        for srv in mapping.get(k, []):
            names.update(t.name for t in _tools_by_server.get(srv, []))
    return [get_tool(n) for n in sorted(names)]


def write_tools() -> list[BaseTool]:
    return list(_tools_by_server.get("executor", []))
```

**逐句要点**：

- `MultiServerMCPClient` 用**字典**配置多 server，一次握手拿全部工具。这是 MCP 相对"自己写一堆 HTTP 调用"的核心价值：**协议统一，客户端代码只有这一份**。
- `get_tools(server_name=...)` 按 server 分别取，是为了后面能做**权限分组**（`readonly_tools()` vs `write_tools()`）。如果一次性全拿，就没法在 `synthesize` 节点上保证"模型看不到 executor 的工具"。
- **启动失败降级**：单个 MCP server 挂掉时记录错误并继续起服务。真实系统里"日志系统在维护"不该导致整个诊断平台不可用。**这是可用性设计，面试可讲。**
