### 2.3 P0 容易卡住的地方

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `python --version` 显示 3.9 / 3.10 | Windows 上有多个 Python，PATH 指到了旧的 | 用 `py -3.12 --version` 确认 3.12 存在即可。**不要纠结系统 `python` 指向谁** —— 按 §3.5 用 `uv python pin 3.12` 把项目锁死在 3.12 |
| **`python --version` 显示 3.14 / 3.13（版本太高）** | 这也是多 Python 环境，而且**更危险**：`requires-python = ">=3.12"` 是"大于等于"，**3.14 也满足，uv 会照着建 3.14 虚拟环境**，和你 Docker 镜像里的 3.12 对不上 | **必须跑 `uv python pin 3.12`**（见 §3.5），在 `uv sync` 之前。跑完 `uv run python -V` 应该打印 `Python 3.12.x` |
| `winget install astral-sh.uv` 报**"找不到与输入条件匹配的程序包"** | 包 ID 没错，是 winget 社区源索引过期或源丢失（只剩 `msstore`，而 uv 不在里面） | 1) `winget source list` 看有没有 `winget` 源 → 2) `winget source update`，不行再 `winget source reset --force` → 3) **最快是直接用 §2.1 的 uv 官方脚本装，绕开 winget** |
| 装完 uv / python 后仍然报"命令找不到" | 终端继承了**旧的环境变量**（Trae / VS Code 的集成终端尤其明显） | **完全退出 Trae（整个程序，不是只关终端面板）再重开**；或单独开一个 Windows PowerShell 验证 |
| `docker` 命令本身找不到 | Docker CLI 没进 PATH，或 Docker Desktop 刚装完还没重开终端 | 关掉终端重开；仍不行就启动一次 Docker Desktop 再重开终端 |
| `docker --version` 有输出，但 `docker run hello-world` 失败 | **只有命令行，引擎没起来**。Docker Desktop "装了"不等于"在运行" | 双击启动 Docker Desktop，等托盘图标变绿（首次 1~2 分钟），再重开终端 |
| `docker run` 报 `npipe:////./pipe/dockerDesktopLinuxEngine` / `error during connect` | Docker 引擎没运行，或 WSL2 没装好 | `wsl --install`（**管理员** PowerShell）→ **重启电脑** → 启动 Docker Desktop → Settings → Troubleshoot → Restart |
| `uv` 命令找不到 | 安装目录没进 PATH | 关掉终端重开一次；官方脚本装的话在 `C:\Users\<你>\.local\bin\uv.exe`，可以直接用全路径 |
| 公司网络/代理下 `winget` 装不了 | 网络策略 | 手动去官网下安装包，不折腾 |

**⚠️ 三个必须处理的（按严重程度排）**：

**① 内存紧张 —— 这是这台机器最大的约束**

实测：物理内存 **15.7 GB**，可用只剩 **741 MB**，已提交 34.2 GB（重度在用页面文件）。
内存大头：`vmmemWSL`（Docker 虚拟机）1.0~1.5 GB、Trae 四个进程合计 ~760 MB、Edge ~370 MB、node 434 MB、网易云音乐 151 MB、Steam 211 MB。

**为什么这事致命**：11 个容器全开要 3~4 GB。在可用 741 MB 的情况下，容器要么起不来，要么被 OOM 杀掉 —— 而**你会误以为是代码写错了**，白白 debug 一整天。

**三件事**：

1. **建 `.wslconfig` 给 WSL2 设上限**（你现在没有这个文件，等于 WSL2 可以吃满物理内存）。用记事本新建 `C:\Users\常浩翔\.wslconfig`，内容：
   ```ini
   [wsl2]
   memory=6GB
   processors=16
   swap=8GB
   ```
   存盘后执行 `wsl --shutdown`（会关掉所有 WSL，包括正在跑的 Docker 容器），再启动 Docker Desktop 生效。
2. **跑容器前先关掉**：Steam、网易云音乐、多余的 Edge 标签、手机连接（PhoneExperienceHost）。能腾出 1 GB 以上。
3. **按层起容器，别一次全开。** compose 已经用 `profiles` 分好层了（见 [03](03-代码指导-基础层.md) §2 的「分层启动」）：`postgres` / `redis` 不带 profile，所以 **`docker compose up -d` 默认只起这两个**，正好是 W1 需要的。MCP 层要 `--profile mcp`，应用层要 `--profile app`，Langfuse 要 `--profile obs`。

**② C: 盘只剩 26.5 GB，而 Docker 的数据在 C:**

实测：`C:\Users\常浩翔\AppData\Local\Docker\wsl\docker_data.vhdx` 已占 **6.0 GB**，C: 只剩 **26.5 GB**。

**为什么要注意**：接下来还要拉 `pgvector/pgvector:pg16`、`redis:7-alpine`、`python:3.12-slim`、构建自己的 app 镜像，再涨 5~8 GB；WSL 的 Ubuntu 发行版也会涨。C: 盘只剩 26.5 GB 是**够用但不宽裕**，且 C: 满了 Windows 本身会出问题。

**两个选择**：
- **省事**：先不管，但每周 `docker system df` 看一次占用，`docker system prune -a` 清理无用镜像。
- **治本**：Docker Desktop → Settings → Resources → **Disk image location** 改到 `D:\docker-data`（D: 剩 208 GB，随便用）。改完原来的镜像要重新拉一遍。

**③ 默认 `python` 是 3.14.3，来自 `D:\tools\python.exe`**

不是 Windows 自带商店版，是你自己装的 3.14。**`requires-python = ">=3.12"` 拦不住它**（"大于等于"），所以 §3.5 的 `uv python pin 3.12` 必须跑。好在你机器上已经有 3.12.10，uv 直接就能用，不需要额外下载。

**其他结论**：

## 5. P3 · 三个探针（Day 3，3h）

> **为什么要有这一步**：这个项目有 3 个技术点你**从来没用过**，而且一旦不通就是"卡好几天"级别的坑：DeepSeek 接口、MCP 双端、LangGraph。
> 花 3 小时把它们各自剥出来，用 10~30 行代码单独验证一次。**跑通了，W2~W7 就都是"填充内容"；跑不通，现在解决比 W4 解决便宜十倍。**
> 探针都放在 `spikes/`，可以提交 git（W3 之后删掉，它不是项目代码）。

### 探针 1 · DeepSeek 通不通（20min）

为什么先做它：**如果 API Key 或余额有问题，后面所有事都做不了。** 而且它验证的是 `langchain-openai` 这个真实依赖，不是别的。

`spikes/spike1_llm.py`：

```python
import os

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model=os.getenv("LLM_MODEL", "deepseek-chat"),
    api_key=os.environ["LLM_API_KEY"],
    base_url=os.getenv("LLM_BASE_URL", "https://api.deepseek.com"),
    temperature=0,
)

msg = llm.invoke("只回复两个字：通了")
print("模型回复：", msg.content)
print("token：", msg.usage_metadata)
```

跑法（**读 `.env` 里的变量**）：

```powershell
# 把 .env 里的 key 读进当前会话
Get-Content .env | Where-Object { $_ -match '^\s*[A-Z]' } | ForEach-Object {
  $k, $v = $_ -split '=', 2
  [Environment]::SetEnvironmentVariable($k.Trim(), $v.Trim(), 'Process')
}
uv run python spikes/spike1_llm.py
```

**✅ 做对了**：打印出模型回复 + 一段 token 数。
**❌ 卡住了**：`401` → key 错或没生效；`402 / Insufficient Balance` → 去充值；连不上 → 检查网络/代理。

### 探针 2 · MCP 双端能不能通（1h）

为什么做它：**MCP 是本项目的定位，也是 W2 整整一周的主题。** 先跑通"一个 server + 一个 client 说上话"，W2 就只是把它复制 4 遍。

`spikes/spike2_mcp_server.py`：

```python
from fastmcp import FastMCP

mcp = FastMCP("probe")


@mcp.tool
def echo(text: str) -> str:
    """原样返回输入文本，用于验证 MCP 通路。"""
    return f"echo: {text}"


if __name__ == "__main__":
    mcp.run(transport="streamable-http", port=8099)
```

`spikes/spike2_mcp_client.py`：

```python
import asyncio

from fastmcp import Client


async def main() -> None:
    async with Client("http://127.0.0.1:8099/mcp") as client:
        tools = await client.list_tools()
        print("工具列表：", [t.name for t in tools])

        result = await client.call_tool("echo", {"text": "hello mcp"})
        print("调用结果：", result)


if __name__ == "__main__":
    asyncio.run(main())
```

跑法（**要两个终端** —— 这是你第一次体会"工具是独立进程"）：

```powershell
# 终端 A：起 server，保持不关
uv run python spikes/spike2_mcp_server.py

# 终端 B：跑 client
uv run python spikes/spike2_mcp_client.py
```

**✅ 做对了**：终端 B 打印工具列表里有 `echo`，并且调用结果为 `echo: hello mcp`。
**❌ 卡住了**：`Connection refused` → server 没起来或端口不是 8099；`404` → 路径不是 `/mcp`。**这两个坑 W2 一定会再遇到一次，现在踩掉最值钱。**
顺手做一次：终端 A 按 `Ctrl+C`，再跑终端 B —— 应该连不上。**"进程没了工具就没了"这件事，就是权限隔离的物理基础。**

### 探针 3 · LangGraph 图能不能跑（30min）

为什么做它：W3~W7 全在图里。先跑一个最傻的两节点图，确认装对了、能 invoke。

`spikes/spike3_graph.py`：

```python
from typing import TypedDict

from langgraph.graph import END, START, StateGraph


class S(TypedDict):
    text: str


def upper(state: S) -> S:
    return {"text": state["text"].upper()}


def tag(state: S) -> S:
    return {"text": state["text"] + " OK"}


g = StateGraph(S)
g.add_node("upper", upper)
g.add_node("tag", tag)
g.add_edge(START, "upper")
g.add_edge("upper", "tag")
g.add_edge("tag", END)

app = g.compile()
print(app.invoke({"text": "hello graph"})["text"])
print(app.get_graph().draw_ascii())
```

跑法：

```powershell
uv run python spikes/spike3_graph.py
```

**✅ 做对了**：打印 `HELLO GRAPH OK`，并且下面画出一张 ASCII 图（能看到 START → upper → tag → END）。
**❌ 卡住了**：`ImportError` → 版本没对齐，去 [03](03-代码指导-基础层.md) §1 的"三个容易踩的依赖坑"看。

| D6 | **手工 SQL 演练** | 无 —— 自己玩 | 插 `status='wrong_status'` 被 CHECK 拦住；`downgrade -1 && upgrade head` 来回跑通 |
| D7 | 缓冲 / 补漏 | — | 补上没做完的，不欠债进 W2 |

**W1 验收（5 条，来自 07）**：

- [ ] `alembic upgrade head` → `\dt` 看到 11 张表
- [ ] `alembic downgrade -1` → `alembic upgrade head` 来回跑通
- [ ] `\d+ executions` 确认 `idempotency_key` 唯一索引存在
- [ ] 手写 SQL 插入 `status='wrong_status'` 的 incident，被 CHECK 约束拦住
- [ ] 断开 Postgres 后 API 报错信息可读（不是一堆堆栈）

> ⚠️ **W1 有一个必踩的坑，提前告诉你**：`.env` 里的 `PG_DSN` 主机名是 **`postgres`**（Docker 内部服务名），不是 `localhost`。
> - **在容器里跑**（api / worker）→ 用 `postgres`
> - **在自己机器上裸跑**（比如 `uv run alembic`）→ 要改成 `localhost`
> 一个 `.env` 两种场景打架，是最经典的"明明装了却连不上"。解决办法：W1 阶段所有命令都在容器里跑（`docker compose run --rm api alembic upgrade head`）。

## 7. 日常怎么用这套文档

### 7.1 日循环 7 步（每天照着走）

```
1. 打开 07，找到"本周 + 今天"那一行           ← 知道今天要干什么
2. 打开对应代码指导文档的对应小节             ← 知道怎么写
3. 干 25~50 分钟，只做这一件事
4. 跑一次，看结果（不是"写完就以为对了"）
5. 卡住超过 30 分钟 → 停，记进疑问清单
6. 当天 commit（哪怕 `WIP: 半成品`）
7. 写一行踩坑日志
```

**第 6、7 步是防烂尾的关键，不要省。** 07 里写的三条防烂尾铁律就是这三条。

### 7.2 卡住怎么办：30 分钟规则

**同一个问题卡满 30 分钟就停手**，按顺序做：

1. **贴报错原文去搜**（不要搜你的中文描述，要搜报错那句话本身）
2. **去对应代码指导文档里搜关键词**（可能是文档已经写了的坑）
3. **缩到最小可复现**：把代码删到只剩报错那几行
4. **还不行就问**（用 §7.3 模板）

**不要做的事**：不要在一个报错上耗一整天，不要"重装一遍试试"，不要同时改三处然后不知道哪处生效了。

### 7.3 提问模板（贴这个，别只说"报错了"）

```
【我在哪一步】07 → W1 → D3
【我想干什么】跑 alembic upgrade head 建 11 张表
【我做了什么】复制了 02 文档的 DDL，命令是 xxx
【报错原文】（完整粘贴，不要摘要，不要截图）
【我试过什么】重启过 postgres 容器，没用
【我猜是】env.py 里 target_metadata 没设对
```

有了这 6 行，问题基本能一次解决。**只说"报错了"会来回好几轮。**
